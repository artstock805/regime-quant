# regime-quant

레짐(시장 국면)을 분류하고, 그 국면에서 검증된 전략의 신호로 진입·청산을 판단하는
**암호화폐 백테스트 · 신호 조회 도구**.

> ## ⚠ 먼저 읽어 주세요
>
> **이 도구로 실매매하지 마십시오. 주문 실행 기능은 코드에 아예 없습니다.**
>
> 129종목 · 7,496 거래 · 2021-12~2026-08 out-of-sample 검증 결과:
>
> | | 값 | 뜻 |
> |---|---|---|
> | 총우위 | +0.0260R (군집 t **3.52**, p=0.0004) | 우위는 **실재한다** |
> | 순우위 | +0.0106R (군집 t 1.42, p=0.154) | **0과 구분되지 않는다** |
> | 비용 | 총우위의 **59%** | 비용이 우위의 절반 이상을 먹는다 |
> | 판정 | **1/5 통과** · Deflated Sharpe 0.865 (기준 0.95) | 실전 근거 아님 |
>
> 기본 설정은 "가장 좋았던 조합"이고, 그건 **여러 조합을 다 본 뒤에 고른 것**입니다.
> 그 선택 편향을 반영한 Deflated Sharpe 가 기준에 미달합니다.
> 투자 조언이 아니며, 손실 책임은 사용자에게 있습니다.

   설치 화면의 **"Add Python to PATH"** 를 반드시 체크하세요.
2. 이 저장소를 받습니다 (`Code → Download ZIP`, 또는 `git clone`).
3. `windows\create-shortcut.bat` 을 더블클릭하면 **바탕화면에 아이콘**이 생깁니다.
4. 아이콘을 누릅니다. **처음 누르면 설치부터 물어봅니다** — 가상환경(`.venv`)에만
   설치하고 시스템 파이썬은 건드리지 않습니다.

`windows\install.bat` 으로 미리 설치해 둘 수도 있지만, 아이콘만 눌러도 됩니다.

아이콘을 누르면 **웹 화면이 브라우저에 바로 열립니다** (http://127.0.0.1:8787).

| 화면 | 내용 |
|---|---|
| **홈** `/` | 판정·설정·데이터 현황 + 기능 버튼 + 실행 로그 실시간 표시 |
| **상황판** `/cockpit` | 검증된 백테스트를 봉 단위로 재생 — 차트·레짐 띠·전략 리더보드·체결 로그 |

홈에서 누를 수 있는 것: 실시간 신호 · 데이터 받기(3단계) · 파생 데이터 ·
백테스트 검증 · 지표 성적표 · 자체 점검.

### 자동 감시 — 켜 두면 알아서 다시 조회합니다

홈의 **자동 감시 토글**을 켜면 고른 주기(1분~1시간)마다 신호를 다시 조회하고,
**상태가 바뀐 종목만** 알립니다. 브라우저 알림도 뜹니다(권한을 허용한 경우).

**주문은 나가지 않습니다.** 감시가 하는 일은 알려 주는 것까지입니다.

설계에서 정한 것 네 가지 — 전부 "켜 두고 잊는" 기능이라 조용한 실패를 막기 위한 것입니다.

| | 왜 |
|---|---|
| 감시는 **자기 슬롯**에서 돈다 | 작업 실행기는 한 번에 하나만 돌린다. 감시가 그 슬롯을 차지하면 다른 버튼이 전부 막힌다 |
| 무거운 작업 중에는 **주기를 건너뛴다** | 둘이 CPU 를 두고 싸우면 둘 다 느려지고 무엇이 멈춘 건지 알 수 없다 |
| 첫 사이클은 **기준만 세운다** | 켜자마자 보유 중이던 종목이 전부 '진입'으로 뜨면 지금 생긴 신호로 읽는다 |
| 끄면 **즉시 꺼진 것으로 표시**한다 | 조회 한 번이 1분 넘게 걸린다. 그동안 '실행 중'이면 안 꺼진 줄 알고 다시 누른다 |

터미널에서는 이렇게 씁니다.

```bash
python scripts/signals.py --watch 300 --only-actionable
```

각 버튼은 `scripts/` 의 명령을 **그대로 subprocess 로 실행**하고 출력을 화면에
흘려보냅니다. 웹용으로 같은 로직을 다시 쓰면 두 벌이 되어 언젠가 갈라지므로,
터미널에서 돌린 것과 글자 하나까지 같은 결과가 나오게 했습니다. 목록에 없는
명령은 실행되지 않습니다 — 웹에서 임의 인자를 받으면 그건 원격 코드 실행입니다.

터미널 메뉴가 필요하면 `windows\install.bat` 대신 `start.bat --menu` 입니다.

### 배치파일은 영문만 담습니다

`windows\*.bat` 에는 한글이 한 글자도 없습니다. cmd.exe 가 배치파일을 **시스템
ANSI 코드페이지**로 읽기 때문에, UTF-8 로 저장한 한글은 깨지고 **깨진 바이트가
명령어로 파싱**됩니다 (`'st'은(는) 명령이 아닙니다`). 한국어 Windows 가 아니면
더 심합니다. 실제로 이것 때문에 바탕화면 아이콘이 아무 일도 안 하는 것처럼
보였습니다.

그래서 배치파일은 파이썬을 찾아 넘기는 것만 하고, 사람이 읽는 글은 전부
`src/launcher.py` 가 출력합니다 — 인코딩을 제어할 수 있는 쪽입니다.
`tests/test_packaging.py` 가 배치파일에 비ASCII 바이트가 들어오면 실패합니다.

### 왜 .exe 설치파일이 아닌가

정직하게 적습니다. 이 도구를 단일 exe 로 묶으면 **파이썬·pandas·numpy·pyarrow 를
함께 담아 300MB 를 넘고**, 서명이 없어서 백신이 흔히 오탐합니다. 게다가 exe 안에
갇힌 코드는 사용자가 읽거나 고칠 수 없습니다 — 백테스트 도구에서 그건 치명적입니다.
검증 결과를 믿으려면 계산 과정을 볼 수 있어야 합니다.

그래서 **설치 배치파일 + 바탕화면 바로가기**로 만들었습니다. 클릭 한 번으로 열리는
경험은 같고, 코드는 그대로 열려 있습니다.

## 실시간 신호 — 주문은 하지 않습니다

```bash
python scripts/signals.py                      # 한 번 조회
python scripts/signals.py --watch 300          # 5분마다
python scripts/signals.py --only-actionable    # 진입·청산만
python scripts/signals.py --json runs/signals.json
```

**백테스트와 같은 인과 규칙을 씁니다.** 신호는 **마감된 봉**의 종가로 계산하고
체결은 **다음 봉 시가**를 가정합니다. 진행 중인 봉으로 판단하면 화면의 신호와
검증 숫자가 다른 것을 가리키게 됩니다.

가중치도 walk-forward 와 같은 방식으로 얻습니다 — **최근 6개월 학습 구간에서만**
전략을 단독으로 돌려 레짐별 기대R 을 뽑습니다. 오늘 성적으로 오늘 가중치를 만들면
그게 미래 참조입니다.

출력에는 종목·동작(롱진입/숏진입/청산/유지/관망)·점수·문턱·국면·손절가·목표가·1R 이
나오고, 상태가 바뀐 종목은 어느 전략이 근거였는지 함께 보여 줍니다.

`src/live/signals.py` 에 주문 관련 코드가 없다는 것을 테스트가 고정합니다
(`tests/test_live_signals.py`) — 검증 1/5 상태에서 주문 경로가 있으면 실수로
열릴 수 있고, 코드에 없으면 실수로 열릴 수 없습니다.

## RBI — Research, Backtest, Implement

이 프로젝트는 **R → B → I** 순서로 돌아간다. 세 단계를 섞지 않는 것이 핵심이다.

| | 하는 일 | 도구 | 상태 |
|---|---|---|---|
| **R** 리서치 | 정보가 어디 있는지 **찾는다** | `screen_features.py` · `orthogonality.py` | 진행 중 |
| **B** 백테스트 | 그 정보가 비용을 넘는지 **거짓말 못 하게 잰다** | `validate.py` · `significance.py` | 완비 |
| **I** 실행 | 검증을 통과한 것만 **돌린다** | `src/server/` | **잠김** |

I 가 잠겨 있는 이유는 B 를 통과한 것이 아직 없기 때문이다. 순서를 지키는 것이
이 프로젝트의 규율이고, 규율을 깨는 순간 남는 것은 백테스트 과적합뿐이다.

## 현재 상태

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | 데이터 파이프라인 (캔들 + 파생) | 완료 |
| 2 | 지표 풀 72종 / 96열 + 인과성 자동검증 | 완료 |
| 3 | 레짐 분류기 + 백테스트 엔진 + walk-forward | 완료 — **합격 0/5** |
| 4 | 상황판 실데이터 연결 | 완료 — 리플레이, 실전 잠금 |
| 5 | 트레이딩뷰 MCP (조회 전용) | 완료 |
| 6 | 파생 시장 데이터 + 증분정보 검정 | 완료 — **1/4, 첫 양수** |

**캔들만 쓴 결론: 5.9년 · 3,171 거래 · 32 창에서 순기대값이 음수다(0/5).**
2년 표본의 긍정적 결과(BNB 샤프 1.32)는 표본 선택의 산물이었다 — 최근 1.5년만
좋았고 2021~2024 는 거의 전 구간 손실이다.

**파생 데이터를 넣자 처음으로 순기대R 이 양수가 됐다.** 미결제약정·펀딩·롱숏비율을
붙여 만든 `taker_flow_momentum` 단독 walk-forward:

| | 캔들만 (8전략) | 테이커 흐름 단독 |
|---|---|---|
| 순기대R | −0.0087 | **+0.0166** |
| 총기대R | +0.0165 (t=1.97) | +0.0497 (t=1.75) |
| 양수 종목 | 1/8 | 5/8 |
| 양수 창 | 11/32 | **12/23 (통과)** |
| 비용 / 총우위 | 152% | 67% |
| 판정 | 0/5 | **1/4** |

**그래도 실전 투입 불가다.** 거래 383건으로 유의성에 4,305건이 필요하고,
무엇보다 **13개 전략 결과를 다 본 뒤에 제일 좋은 것을 고른 것**이다. 그 선택
편향을 반영하는 Deflated Sharpe 가 시험 50회 기준 0.086 (기준 0.95) 이다.

### 129종목으로 넓힌 결과 — 우위는 실재하고, 비용이 전부를 먹는다

생존편향 없는 129종목(폐지 44개 포함) · 5,105 거래 · 2021-12~2026-08:

| | 8종목 | **129종목** |
|---|---|---|
| 거래 | 383 | 5,105 |
| 총기대R | +0.0497 (군집 t 1.74) | **+0.0304 (군집 t 3.08, p=0.0021)** |
| 순기대R | +0.0166 (t 0.58) | +0.0062 (t 0.63) |
| 비용 / 총우위 | 67% | 79% |
| 유효표본 | 378 / 383 (99%) | 2,980 / 5,105 (58%) |
| 양수 종목 | 5/8 | 49/90 (54%) |
| DSR (시험 50회) | 0.086 | 0.332 |
| 판정 | 1/5 | **0/5** |

**총우위는 군집 보정을 통과했다** — t=3.08, p=0.0021. 이 프로젝트에서 처음으로
"우위가 실재한다"를 통계로 말할 수 있는 지점이다. 생존편향을 없앤 유니버스에서,
종목 간 상관을 보정한 뒤에도 남았다.

**순기대값은 여전히 0과 구분되지 않는다.** 비용 0.0242R 이 총우위 0.0304R 의
79% 를 먹는다. 필요한 것은 더 좋은 전략이 아니라 **비용 55% 절감**이다:

| 비용 배수 | 순기대R | 군집 t |
|---|---|---|
| 1.0 (현재) | +0.0062 | 0.63 |
| 0.6 | +0.0159 | 1.60 |
| **0.45** | +0.0170 | **1.96** ← 손익분기 |
| 0.4 | +0.0207 | 2.09 |
| 0.0 | +0.0304 | 3.08 |

**슬리피지 과소평가가 만든 결론이 아니다.** 유동성 3분위로 갈라 보면 우위가
오히려 **유동성 높은 쪽에 더 많다**(최고 분위 +0.0373 t=2.51, 최저 +0.0209 t=1.47).
소형 알트에 몰려 있었다면 같은 슬리피지를 매긴 탓으로 봐야 했다.

**사전 예측과 대조** — 확장 전에 "군집 t ≈ 1.10, 유의 미달"로 못박았다.
결론은 맞았지만 **메커니즘은 틀렸다**: 유효표본은 예측(3.57배)보다 많이
늘었는데(7.89배), 거래당 기대값이 62% 떨어져(+0.0166→+0.0062) 상쇄됐다.
추가한 121종목은 대형 8종목보다 우위가 얇다.

이 프로젝트의 실질적 산출물은 전략이 아니라 **거짓말을 못 하게 만드는 B 단계**다.
미래참조 자동검사, 봉내부 선착 판정, 유의성·다중검정·Deflated Sharpe·순열검정이
갖춰져 있어 "잘 나온 결과가 우연인지"를 판별할 수 있다. 실제로 그 도구가 이
프로젝트의 결론을 네 번 기각했다.

검증 단계에서는 **바이낸스 USDT-M 무기한선물** 데이터로 롱숏을 전제한다.
실행 거래소는 백테스트 합격 기준을 통과한 뒤에 결정한다.

**검증된 백테스트 결과를 봉 단위로 재생한다.** 엔진을 스트리밍용으로 고쳐 쓰지 않은
이유는, 엔진에 체결 순서·봉내부 선착 판정을 검증하는 테스트가 붙어 있고 그걸 흔들면
화면의 숫자를 믿을 수 없게 되기 때문이다. walk-forward 를 완주해 결과를 얻고 그것을
되돌려 보여주므로, **화면의 모든 숫자는 백테스트가 실제로 산출한 값이다.**

화면 구성 (탭 없는 단일 화면)

| 패널 | 내용 |
|---|---|
| 차트 | 캔들 + 레짐 배경 띠 + 진입/청산 마커 + 평단선. 마우스 크로스헤어 |
| 전략 리더보드 | 그 창의 **학습 구간** 성적과 가중치. `참여 / 제외 / 표본부족` 상태 표시 |
| 규칙 엔진 로그 | 봉마다 레짐 판정 근거(ADX·효율·톱질·BBW백분위) → 투표 → 합산 → 진입/보류 |
| 체결 로그 | 진입은 **판단 시점 점수**, 청산은 사유·순손익·R배수·수수료 |
| 포지션 | 평단·미실현 R·리스크 금액·명목가·진입 전략·진입 레짐 |
| 누적 손익 | out-of-sample 수익률(거대 숫자) + 자산곡선 + 샤프/MDD/승률/PF |
| 창별 성적 띠 | 32개 창의 합계 R을 막대로. **이익이 한 창에 몰려 있는지** 한눈에 보인다 |

재생 컨트롤: `Space` 재생/정지, `←` `→` 한 봉씩, 1×~60× 속도, 스크럽, 창 막대 클릭 이동.

**실전 모드는 잠겨 있다.** 합격 기준 0/4 이므로 화면 상단에 잠금 사유가 표시되고
버튼이 비활성이다. 리플레이만 동작한다.

### 화면이 설계 원칙을 그대로 보여준다

- **판단과 체결이 분리돼 있다.** 체결 로그의 진입 행은 `점수 0.77` 처럼 **직전 봉**의
  판단 점수를 보여준다. 이번 봉 점수와 나란히 놓으면 "점수 미달인데 진입했다"로
  오해하기 때문이다. 프레임에 `semantics` 필드로 의미를 명시한다.
- **국면 밖 전략은 발언권이 없다.** 횡보 구간에서는 두 모멘텀 전략의 가중치가 0이 되고
  로그에 "발언권 있는 전략 없음"이 뜬다.
- **성적이 나쁜 전략은 제외된다.** 학습 기대R이 음수면 리더보드에 `제외`로 남고
  가중치 0을 받는다 — 왜 빠졌는지 보이게 남겨 둔다.

## 검증 인프라

**이 프로젝트의 실질적 산출물은 전략이 아니라 이 도구 모음이다.** "잘 나온 결과가
우연인지"를 판별하고, 실제로 이 프로젝트의 결론을 여섯 번 기각했다.

```bash
python scripts/validate.py                  # 전체 (순열 포함, 약 30분)

python scripts/validate.py --compare        # 지난 실행들 나란히 비교
python scripts/validate.py --rerender full  # JSON 에서 HTML 만 재생성
```

결과는 `runs/<타임스탬프>/report.{json,html}` 에 남는다. **설정 스냅샷과 환경
정보(파이썬·pandas 버전·git 커밋)가 함께 들어가므로, "그때 무슨 설정으로 그 숫자가
나왔나"에 답할 수 있다.** JSON 이 원본이고 HTML 은 그것을 그린 것이라, 표현을 고쳐도
비싼 계산을 다시 돌릴 필요가 없다.

### 판정 항목 다섯 개

| 검정 | 묻는 것 |
|---|---|
| 통합 순기대R > 0 | 전 종목 거래를 합친 기대값이 0보다 유의하게 큰가 (주 증거) |
| 부호 검정 | 한 종목 요행이 아니라 대부분에서 양수인가 (이항검정) |
| 다중검정 보정 후 유의 | Holm 보정을 통과한 종목이 하나라도 있는가 |
| 창별 양수 과반 | 검증 창의 절반 이상이 양수인가 + 이익 집중도 |
| **순열 검정** | **신호 순서를 흩어도 같은 성과가 나오지는 않는가** |

부가로 Deflated Sharpe(시험 횟수 반영), 파라미터 고원, 비용 손익분기 배수,
워크포워드 효율, 데이터 감사가 함께 나온다.

### 도구가 검증되는 방식

검증 도구가 틀리면 그 위의 모든 결론이 무의미하다. 그래서 도구 자체를 검사한다.

- **알려진 정답으로** — `norm_ppf(0.975) = 1.959964`, 이항 7/8 = 9/256 손계산
- **순열 검정 기계 자체** — 미래를 보는 신호(다음 봉 방향)를 넣으면 귀무분포를
  압도해야 하고, 무작위 신호를 넣으면 압도하지 못해야 한다. 둘 다 확인한다.
- **고원 vs 절벽** — 평평한 곡선은 고원으로, 뾰족한 봉우리는 과최적화로 판정하는지
- **음수 합계에서의 집중도** — 이익 집중도가 음수로 나오지 않는지 (실제 버그였다)

### 단독 IC 는 틀린 질문이었다

파생 최고 |IC| 0.0308 vs 캔들 최고 0.0441 — 단독으로는 못 넘는다. 여기서
멈추면 오답이다. **캔들 상위 8개 특징의 유효 차원이 1.50 / 8** 이다.
평균 상관 0.777, 최대 0.983 — 여덟 개가 사실상 한 개다.

물어야 할 것은 "IC 가 더 높은가"가 아니라 **"이미 아는 것을 걷어내도 남는가"** 다.

| 특징 | 단독 IC | 부분 IC | 캔들과 겹침 |
|---|---|---|---|
| `perp_taker_ls` | +0.0158 | **+0.0203** | 0.120 |
| `oi_zscore` | −0.0179 | −0.0145 | 0.142 |
| `oi_change` | −0.0180 | −0.0126 | 0.165 |
| `oi_price_regime` | −0.0361 | −0.0088 | 0.766 |

`oi_price_regime` 은 단독 1위였는데 걷어내니 무너진다 — 가격 모멘텀을 다르게
부른 것이었다. 반대로 `perp_taker_ls` 는 걷어낼수록 **강해진다**.

캔들 8개에 파생 11개를 더하면 R² 가 0.182% → 0.322%. 무작위 11개를 더했을 때가
+0.007%p 이므로 **과적합 기준선의 19배**다. 이 예측대로, 유일하게 순기대R 이
양수인 전략이 `perp_taker_ls` 로 만든 것이었다.

4종을 짰는데 승률 54.8% 로 높았지만 기대R 은 −0.0158 로 모멘텀(+0.0325)보다
나빴다. **IC 는 평균 방향만 알려 주고 손익 분포의 비대칭을 반영하지 못한다.**
그래서 파생에서도 IC 부호는 가설의 출발점일 뿐이고 채택은 기대R 이 정한다.

## 메이커 수수료 — 프로젝트 최대의 개선, 그리고 앞선 판단의 정정

```bash
python scripts/validate.py --derivatives --calibrate-strength     --entry-threshold 0.85 --fee-rate 0.0002 --universe runs/universe_final.json     --strategies taker_flow_momentum
```

**앞서 "메이커는 8종목에서 역효과였다"고 기록했는데, 129종목에서는 명확히 도움이 된다.**
8종목에서 관찰한 거래 구성 희석(수수료가 낮아지면 진입이 늘고 한계 거래 품질이
떨어지는 현상)이 규모에서 재현되지 않았다 — 거래가 6,725 → 7,496 으로 11% 만 늘었다.

| | 테이커 0.05% | **메이커 0.02%** |
|---|---|---|
| 거래 | 6,725 | 7,496 |
| 총기대R | +0.0278 (군집 t 3.64) | +0.0260 (군집 t 3.52) |
| **순기대R** | +0.0040 | **+0.0106** |
| 순 t (순진 / 군집) | 0.65 / 0.52 | **1.82 / 1.42** |
| **비용 / 총우위** | 86% | **59%** |
| 양수 종목 | 54/97 (p=0.155) | 58/101 (p=0.082) |
| 양수 창 | 15/26 | 15/26 |
| Deflated Sharpe (시험 8 / 50) | 0.964 / 0.829 | **0.974 / 0.865** |
| 판정 | 1/5 | 1/5 |

순기대값이 2.6배가 되고 t 가 0.52 → 1.42 로 올랐다. 비용이 우위의 86% 에서 59% 로
내려간 결과다. **이 프로젝트에서 순우위를 움직인 유일한 수단이다.**

### 그래도 아직 1/5 다

t=1.96 까지 유효표본이 1.89배 필요하다 — 유효율 61% 가 유지되면 거래 14,188건,
연 1,578건이므로 **약 4.2년치 추가 데이터**다. 지금 늘릴 수 있는 표본이 아니다.

비용을 더 줄이면 닿는다:

| 비용 배수 | 순기대R | 군집 t |
|---|---|---|
| 1.0 (메이커) | +0.0106 | 1.42 |
| 0.8 | +0.0137 | 1.84 |
| **0.6** | +0.0167 | **2.26** ← 유의 |
| 0.0 | +0.0260 | 3.52 |

메이커 위에서 남은 비용은 슬리피지(왕복 4bp)다. 그것까지 40% 줄이면 유의해진다.

### 백테스트가 모델링하지 않은 위험

**메이커 주문이 항상 체결된다고 가정한다.** 지정가는 가격이 오지 않으면 체결되지
않고, 체결되는 경우는 가격이 그쪽으로 왔을 때 — 즉 **불리한 방향으로 움직일 때
더 잘 체결된다**(역선택). 모멘텀 신호는 빠른 움직임에서 발생하므로 이 효과가 특히
크다. 실전 메이커 수익률은 이 백테스트보다 나쁠 것이고, 얼마나 나쁠지는 호가
데이터 없이는 알 수 없다. **메이커 결과를 실전 근거로 삼으려면 페이퍼 트레이딩에서
실제 체결률을 먼저 재야 한다.**

## 지표 성적표 — 정기적으로 지표를 재고, 그 순위를 의심한다

```bash
python scripts/scoreboard.py --universe runs/universe_final.json --derivatives
python scripts/scoreboard.py --show          # 계산 없이 지난 결과만
```

`runs/scoreboard/<타임스탬프>.json` 에 쌓이고, 직전 스냅샷과 비교해 **새로 추가된
지표**와 순위 변동을 보여준다.

**순위표는 만들기 쉽고 믿기 쉽다.** 96개를 수익성으로 줄 세워 1등을 고르면 그건
시험 96회다. 그리고 같은 종류의 순위가 쓸모없다는 것을 이미 측정했다 — 종목 성적의
분기 순위 지속성이 +0.024(t=0.36) 였고, 그 순위를 믿고 최악을 뺐더니 기대값이
-0.0087 에서 -0.0113 으로 **악화**됐다.

그래서 출력 순서를 뒤집었다. **지속성을 먼저, 순위를 나중에** 보여준다.

    [1] 이 순위를 믿을 수 있는가   지속성(순열 검정) · 상위 k 유지율 · Holm 통과 개수
    [2] 순위
    [3] 하위
    [4] 지난 성적표와 비교          새 지표 · 10계단 이상 이동 · 누적 시험 횟수

**미래 참조를 막은 방식**: 지표값이 높을 때 오르는지 내리는지를 전 구간으로 정하면
그게 미래 참조다. 기간을 나누고 **각 기간의 방향과 문턱을 직전 기간에서만 배운다.**
채점이 자동으로 기간외가 되고, 동시에 지속성이 측정된다 — 방향이 유지되지 않는
지표는 점수가 저절로 나빠진다.

**기대R 은 근사값이다.** 봉 내부 손절·목표 선착을 판정하지 않으므로 절대 수준은
실제보다 낙관적이다. 모든 지표에 같은 잣대를 쓰므로 순위 비교에만 쓴다.

도구 자체도 검증한다(`tests/test_scoreboard.py`, 17개) — 순수 잡음이면 "지속성 없음",
진짜 예측력이 있으면 찾아냄. 잡음에 대고 "순위가 유지된다"고 말하는 성적표는
없는 것보다 나쁘다. **그 검사가 실제로 버그를 잡았다**: 순열 귀무분포를
`n_perm // 100` = 10개만 뽑고 있었다. p 해상도가 0.1 이고 관측이 그 10개를 넘기만
하면 p=0 이 찍혀 없는 패턴을 찾았다고 말한다. 순위를 표준화해 내적 한 번으로
만들어 2,000회 전부 돌게 고쳤다.

3종목 시범 실행에서 **67개 지표 전부 기대R 이 음수**였고 Holm 통과는 0개였다.
1등이라는 것이 "가장 덜 나쁜 것"이라는 뜻이다. 성적표가 자기 무용함을 정직하게
보고한 것이므로 설계 의도대로 동작한 것이다.

## 4시간봉은 답이 아니었다 — 비용은 줄지만 우위가 사라진다

비용/1R 은 실제로 절반이 된다. 비용은 가격 대비 고정이고 1R = 4×ATR 이므로,
ATR 이 두 배인 타임프레임에서는 같은 수수료가 1R 의 절반만 차지한다.

| | 1시간봉 | 4시간봉 |
|---|---|---|
| 비용 / 1R | 5.2% | **2.5%** |
| 신호 발생률 | 72.5% | 72.6% |

그런데 실측 결과는 반대였다. 129종목 · 456거래:

    총기대R -0.0485  (t=-2.02, 군집 -1.87)   ← 우위 자체가 음수다
    순기대R -0.0604  (t=-2.51, 군집 -2.34)

**비용이 우위를 먹는 게 아니라 우위가 없다.** 타임프레임을 통한 비용 절감 경로는
이 전략에서는 막혔다.

### 그 과정에서 드러난 설계 불일치

거래가 456건뿐이었다. 원인을 추적하니 **문턱과 확신도의 척도가 어긋나 있었다.**

| | 1시간봉 | 4시간봉 |
|---|---|---|
| 확신도 중위 | 0.104 | 0.091 |
| 문턱(0.35) 초과 비율 | 15.1% | 11.4% |
| 가중치 0 인 창 | 13/25 | 15/25 |

`taker_flow_momentum` 은 진입 조건을 `|z|>=0.15` 로 선언하는데 확신도를
`scale(|z|, 0.15, 2.0)` 으로 만든다. 중위가 0.104 라서 문턱 0.35 는 실질적으로
`|z|>=0.80` 을 요구한다 — **선언한 조건과 5배 어긋나고, 신호의 85~89% 가 설계
의도와 무관하게 버려진다.** 게다가 창의 절반 이상에서 학습 성적이 나빠 가중치가
0이 되어 그 창은 거래가 아예 없다.

문턱 하나가 전략마다 다른 뜻을 갖는 구조는 비교가 성립하지 않는다. 그래서
확신도를 **자기 최근 신호 분포의 백분위**로 바꾸는 옵션을 넣었다
(`WeightParams.calibrate_strength`, `validate.py --calibrate-strength`).
그러면 문턱 0.35 는 어디서나 "내 최근 신호 중 상위 65%"를 뜻한다.

**기본은 꺼 둔다.** 켜면 결과가 바뀌므로 새로운 시험 한 번이고 Deflated Sharpe 가
그만큼 깎인다. 끈 것과 켠 것을 나란히 재고 고르는 것이 정직하다.

## 대량 수집에서 배운 것

**아카이브 서버는 간헐적으로 5xx 를 낸다.** 134종목 수집에서 4종목이 503 으로
실패했고, 4시간봉 검증은 BATUSDT 한 장의 503 으로 129종목 실행 전체가 죽었다.
지수 백오프 재시도(최대 4회)를 넣었다. 영구 오류(403 등)는 재시도하지 않고 바로
올린다 — 조용히 삼키면 원인을 못 찾는다.

**없다고 확인한 구간을 다시 훑지 않는다.** 대부분 종목의 아카이브는 2021-12 부터인데
백테스트 시작은 2020-10 이다. 404 는 정상적인 '없음'이라 조용히 넘어가므로 눈에
띄지 않는데, 종목당 430일 × 129종목 = **실행마다 5만 5천 번의 헛요청**이었다.
`<캐시>.probe.json` 에 "여기보다 앞은 없다"를 기록해 다시 묻지 않는다.

## 유니버스를 넓힐 때 생기는 두 가지 함정

거래 383건으로는 유의성에 4,305건이 모자란다. 종목을 늘리는 것이 답인데,
늘리는 방식이 틀리면 **없는 우위를 만들어낸다.**

### 1. 생존편향 — 사라진 종목이 34%다

```bash
python scripts/fetch_universe.py          # 상장폐지 종목까지 받는다
```

지금 상장된 종목만 쓰면 안 된다. 아카이브에 2021-12 데이터가 있는 USDT 무기한
**134개 중 44개(33%)가 이미 상장폐지**됐다 — LUNA, FTM, SRM, BZRX 처럼 무너진
것들이다. 이들을 빼면 "살아남을 종목만 골라 거래한" 결과가 되고 실전에서 재현할 수 없다.

종목 선정 규칙은 사전에 적용 가능한 것만 쓴다 — **2021-12-01 에 아카이브가
존재했는가**. 오늘의 거래대금으로 고르면 그 자체가 미래 정보다.

실제로 받은 결과: 후보 134 → **사용 가능 129종목**(5개는 1h·1m·파생 중 하나가
부족해 제외). 1시간봉 512만 개, 파생 5,418만 행, 약 9GB. 165분 소요.
4종목이 503 으로 실패했으나 재시도로 전부 복구됐다 — 아카이브 서버는 간헐적으로
죽으므로 대량 수집에는 재시도가 필요하다.

데이터는 `D:/regime-quant-data` 에 둔다(`config/config.yaml` 의 `paths`).
1분봉이 종목당 90MB 라 C 드라이브에 들어가지 않는다.

### 2. 상관 — 거래를 16배로 늘려도 정보는 16배가 아니다

암호화폐 알트는 서로 0.8 이상 상관돼 있다. 같은 주에 134종목에서 열린 거래는
독립 관측 134개가 아니라 **같은 시장 충격을 134번 센 것**에 가깝다. 순진한
t검정은 이걸 독립으로 세므로 t 가 √134 배까지 부푼다.

`src/validation/stats.py` 의 `clustered_mean_test()` 가 주 단위 군집 강건
표준오차로 이걸 막는다.

    Var(mean) = (1/N²) · Σ_g ( Σ_{i∈g} (x_i - mean) )²

검증 스위트에 판정 항목으로 넣어 두었으므로 우회할 수 없다. 리포트에
**SE 팽창률**과 **유효표본**(거래의 몇 %가 독립 정보인가)이 함께 찍힌다.

도구 자체도 검증한다(`tests/test_clustered_stats.py`) — 독립 데이터에서는 순진한
SE 와 같아야 하고, 같은 신호를 16번 복제하면 순진한 |t| 는 4배로 뛰지만 군집 t 는
제자리여야 한다. 후자가 이 도구의 존재 이유다.

거래 수가 적은 종목은 부호검정에서 표를 주지 않는다(`min_trades_per_symbol=30`).
상장폐지로 몇 달치만 남은 종목의 기대값 부호는 동전던지기다.

## 지표 구현 대조

지표를 직접 구현하면 **정의를 잘못 구현해도 자기 자신과는 완벽히 일관**하므로
인과성 검사도 벡터화 동치 검사도 전부 통과한다. 외부 기준이 있어야 드러난다.

```bash
pytest tests/test_reference_parity.py        # 권위 있는 검증
python scripts/crosscheck_indicators.py      # 참고용 트레이딩뷰 대조
```

`test_reference_parity.py` 가 기준이다 — `ta` 라이브러리와 **같은 데이터·같은
파라미터**로 전 구간을 대조하고 오차 0.000% 를 요구한다. 실측 결과 RSI·ATR·ADX·
MACD·Williams %R·MFI·OBV 가 전부 정확히 일치한다.

Wilder 평활(RSI·ATR·ADX)은 초기 시딩 방식이 라이브러리마다 달라 앞쪽 몇백 봉에서
값이 다르다. 지수적으로 감쇠해 **200봉에서 0.000003%, 400봉에서 0** 이 된다.
정의 차이가 아니므로 수렴 구간에서 비교하고, 수렴한다는 사실 자체도 테스트로 고정한다.
OBV 는 시작점이 임의라 상수 오프셋이 생기므로 차분으로 비교한다.

**이 대조가 실제로 버그를 잡았다 — CCI.** 평균편차를 각 봉의 자기 이동평균 기준으로
계산하고 있었다. 표준은 그 윈도우의 단일 평균 기준이다. 5분봉 18%, 1시간봉 21%,
일봉 1% 어긋난 채로 모든 내부 검증을 통과하고 있었다(이동평균이 빠르게 움직이는
짧은 타임프레임일수록 오차가 커진다). 수정 후 세 타임프레임 모두 0.0000% 일치.

**트레이딩뷰는 검증 기준이 아니다.** 계산 윈도우와 파라미터가 공개돼 있지 않고
자체 집계 피드를 쓴다. `ta` 와 0.000% 일치하는 지표도 트레이딩뷰와는 몇 % 씩
어긋난다. `crosscheck_indicators.py` 는 자릿수가 통째로 다른 오류를 먼저 잡는
참고용으로만 남겨 뒀다.

## 테스트

```bash
python -m pytest -q
```

네트워크 없이 돌리려면:

```bash
python -m pytest -q -m "not network"
```

### 이 프로젝트에서 가장 중요한 테스트

`tests/test_causality.py` 는 등록된 지표 **전부**에 대해 미래 참조(look-ahead)를 검사한다.

> 시점 t의 지표값이 t 이하의 데이터만으로 결정된다면, 데이터를 t에서 잘라 계산해도
> t의 값은 같아야 한다. 다르다면 그 지표는 미래를 훔쳐본 것이고, 백테스트 수익률은
> 전부 거짓이다.

새 지표를 추가하면 검사 대상에 자동 포함되므로, 미래 참조를 들고 들어오면 바로 걸린다.

`tests/test_vectorized_equivalence.py` 는 성능 때문에 벡터화한 프리미티브
(`linreg_slope`, `linreg_r2`, `percent_rank`, `aroon`)가 소박한 참조 구현과
같은 값을 내는지 비교한다. 빠르지만 틀린 지표는 느린 지표보다 나쁘다.

## 설계 결정과 그 이유

**비용은 봉 크기가 아니라 손절폭과 비교해야 한다.** 처음에는 "왕복 0.11%를
1분봉은 못 넘기지만 5분봉은 넘긴다"고 판단해 5분봉을 기본으로 잡았다. 이 판단은
틀렸다 — 비교 대상이 봉 크기가 아니라 **1R(손절폭)** 이기 때문이다.
BTC 5분봉 ATR은 0.15%뿐이라 1.5×ATR 손절은 0.23%이고, 왕복 비용 0.11%가
**1R의 47.8%** 를 차지한다. 이 상태에서 2:1 목표의 손익분기 승률은 49.3%로
도달 불가능하다. 그래서 검증 기준을 1시간봉 4×ATR(비용 3.5%)로 옮겼다.
아래 '비용 구조' 표가 타임프레임 선택의 실제 근거다.

**1분봉은 체결 판정용으로 받는다.** 5분봉 안에서 손절과 목표 중 무엇이 먼저 닿았는지는
5분봉만으로는 알 수 없다. 이걸 얼버무리는 것이 백테스트에서 가장 흔한 거짓말이다.
1분봉이 없으면 백테스터는 "손절이 먼저"라는 보수적 가정을 강제한다.

**상위 타임프레임은 닫힌 뒤에만 쓴다.** 1h 봉 11:00 은 12:00 에 닫히므로, 11:05 의
5m 봉이 볼 수 있는 최신 1h 값은 10:00 봉이다. `resample.align_higher` 가 이를 강제하고
테스트가 검증한다.

**돈치안 채널 상단은 직전 봉까지의 최고가다.** 현재 봉의 고가를 포함하면 현재 봉이
항상 채널 안에 있게 되어 돌파가 절대 잡히지 않는다.

**미완성 봉은 버린다.** `fetch_klines(closed_only=True)` 가 기본값이다. 아직 닫히지
않은 봉으로 신호를 만들면 실전에서 재현되지 않는다.

## 강건성 검정 (`scripts/robustness.py`)

"8종목 중 하나가 샤프 1.32를 넘었다"는 근거가 되지 않는다. 다섯 갈래로 검정했다.

| 검정 | 결과 | 판정 |
|---|---|---|
| **통합** 순기대R (전 종목 거래 합산) | +0.0199, t=1.26, p=0.21 | ✗ 0과 구분 안 됨 |
| **통합** 총기대R (비용 제외) | +0.0480, **t=3.03, p=0.0025** | ✓ 우위는 실재 |
| **부호 검정** — 몇 종목이 양수 | 7/8, p=0.035 | ✓ 일관성 있음 |

### 이 검정이 드러낸 것 세 가지

**1) BNB의 샤프 1.32는 지표의 함정이었다.** 자산곡선 기반 샤프는 노출이 낮으면
(BNB는 5.6%) 분모인 변동성이 작아져 부풀려진다. **거래 단위**로 보면 t=1.40,
p=0.16 으로 다중검정 보정 이전에도 유의하지 않다. 낮은 노출에서 자산곡선 샤프를
믿으면 안 된다.

**2) 수익 전체가 한 창에 몰려 있다.** 2026-01~03 창 하나가 전체 수익의 116%다.
즉 그 두 달을 빼면 8종목 통합이 손실이다. 재현 가능한 우위가 아니다.

**3) 종목을 8개로 넓히자 명확한 손실 종목이 나왔다.** LINKUSDT −6.51%(샤프 −1.25).
5종목까지는 전부 양수였다 — 표본을 늘려야 보이는 것이 있다.

### 그래도 남는 신호

두 가지는 통과했고, 방향이 무의미하다는 뜻은 아니다.
- **총기대R +0.0480 (t=3.03, p=0.0025)** — 비용을 제외한 우위는 통계적으로 실재한다.
- **7/8 종목 양수 (p=0.035)** — 한 종목 요행이 아니다.

비용이 우위의 **58%** 를 먹는다(0.0281R / 0.0480R).

### 비용 절감도 답이 아니었다 — 실측으로 확인

"비용을 절반으로 줄이면 순기대R이 0.020 → 0.034, t가 1.26 → 2.1 이 되어 유의해진다"고
계산했다. **이 계산은 틀렸다.** 메이커 수수료(0.02%)로 8종목을 다시 돌린 결과:

총기대R과 부호 검정은 오히려 악화됐다.

원인은 **거래 구성의 변화**다. 수수료가 낮아지면 일일 손실 한도에 덜 걸리고 자본이

비용만 빼서 예측할 수 없다.

**이것이 남긴 실행 가능한 정보**: 한계 거래가 평균보다 나쁘다면, 반대로

| 2종 · 6×ATR · 메이커 · 적응형청산 | 0.66 | 0.50 | −0.57 | 적응형이 고정보다 나쁨 |

### 진단: 왜 미달인가

**1) 우위는 실재한다. 비용이 그 89%를 먹는다.** `scripts/significance.py` 로 검정한
결과, **총**기대R(비용 제외)이 통계적으로 유의하게 양수인 전략이 둘 있다 —
돈치안 채널 돌파 +0.0392R(t=2.51, CI [+0.010, +0.070]), EMA 크로스 +0.0325R(t=2.09).
반면 **순**기대R이 유의하게 양수인 전략은 0개다. 돈치안의 순 +0.0059R 은 t=0.38 로
0과 구분되지 않고, 유의해지려면 25,186 거래가 필요하다(현재 891).
→ 처방은 "더 좋은 전략"이 아니라 **비용 절감**이다.

**2) 레짐 게이팅은 유지해야 한다.** 게이팅을 끈 대조군에서 MDD가 1.4~2.5배 커졌다
(BTC 4.21% → 10.35%, 수익률 +4.69% → −4.14%). 게이팅의 값은 트레이드당 기대값을
올리는 게 아니라 **거래를 절반으로 줄여 낙폭을 억제**하는 데 있다.
개별 전략의 국면 안/밖 총기대R 차이는 평균 +0.0024R 로 미미했지만, 위험조정
성과로 보면 명확히 낫다. 두 측정이 다른 것을 재고 있었다.

**3) 평균회귀 전환은 실패했다 — IC 부호만 보고 방향을 정하면 안 된다.**
특징 스크리닝에서 상위 정보계수가 전부 음수였다(dc_pos −0.037, bb_pct_b −0.036,
rsi −0.033). 그래서 평균회귀 4종을 새로 짰지만 결과는 모멘텀이 더 좋았다:
모멘텀 총기대R **+0.0325** vs 평균회귀 **−0.0158**. 평균회귀는 승률 54.8%로 높은데
기대R이 나쁘다 — **작게 여러 번 이기고 크게 진다.** IC는 평균 방향만 알려주고
손익 분포의 비대칭(꼬리 위험)을 반영하지 못한다. 전략을 10종으로 늘린 walk-forward는
6종보다 나빴다(BTC +4.32% → −0.51%).

**4) 전략은 넓히는 게 아니라 좁혀야 했다.** 유의한 우위가 있는 2종만 남기자
5종목 전부 양수가 됐다. 평균회귀 6종은 유의한 음의 우위였다(VWAP 회귀 t=−2.74,
추세 과열 되돌림 t=−3.03) — 넣을수록 손해였다.

**5) 적응형 청산은 실측에서 도움이 안 됐다.** 레짐별 최적 손익비가 갈렸으므로
(하락추세·고변동 2.0 / 횡보 1.0) 학습 구간에서 뽑아 검증에 적용하는 장치를
`ExecParams.reward_by_regime` + `walk_forward(adaptive_exit=True)` 로 구현했지만,
고정 1.5:1 보다 나빴다(BTC 샤프 0.97 → 0.66). 레짐별 표본이 작아 뽑은 값이
잡음이었을 가능성이 크다. 기능은 남겨 두었고 기본값은 고정이다.

**6) 가중치가 창마다 흔들린다.** 창간 표준편차가 평균보다 큰 칸이 있었다
(횡보의 VixFix 0.292 ± 0.440). 전략을 2종으로 줄이면서 완화됐지만 여전히 감시 대상이다.

### 비용 구조 — 타임프레임 선택의 근거

왕복 비용 0.110%(테이커 0.04%×2 + 슬리피지 1.5bp×2)가 1R에서 차지하는 비율:

| 타임프레임 | 손절 1.5×ATR | 2.5×ATR | 4.0×ATR |
|---|---|---|---|
| 5분 | 27.2% | 19.8% | 13.3% |
| 15분 | 18.4% | 11.6% | 7.4% |
| 1시간 | 9.3% | 5.6% | 3.5% |

2:1 손익비의 손익분기 승률은 `(1 + 비용R) / 3` 이다. 5분봉 1.5×ATR 에서는
42.4% 가 필요한데, 이는 2:1 목표로는 사실상 도달 불가능하다. 그래서 1시간봉
4×ATR(비용 3.5%)을 검증 기준 설정으로 삼았다.

## 알려진 함정 (실측으로 확인)

**바이낸스 CSV 덤프에 헤더 줄이 있는 파일과 없는 파일이 섞여 있다.**
중간에 추가됐다. `_read_dump_zip` 이 첫 칸의 숫자 여부로 판별한다.

**`open_time` 단위가 파일에 따라 밀리초 / 마이크로초로 다르다.**
`_epoch_to_utc` 가 값의 크기로 판별한다. 판별하지 않으면 1970년이나 55000년에 찍힌
인덱스가 조용히 섞여 들어와 백테스트 전체가 어긋난다.

**pandas 3.0 에서 `astype("int64")` 는 나노초가 아니라 해당 해상도의 정수를 준다.**
ms 해상도 인덱스에 `.astype("int64") // 1_000_000` 을 걸면 값이 1970년으로 뭉개진다.
정규화를 소스마다 즉시 하고, 원본 열 모양으로 되돌리지 않는 것이 해법이다.

**가중치 상한이 실현 불가능하면 확신도가 조용히 깎인다.** 적격 전략이 2개인데
상한이 0.45면 합의 최대가 0.90 이라 정규화가 성립하지 않는다. 이 버그가 있던
동안 BTC의 OOS 성적이 −4.65%(샤프 −0.95)로 나왔고, 상한을 1/n 으로 완화하자
+4.69%(샤프 0.75)가 됐다. 부호가 뒤집히는 크기의 버그였다.
`tests/test_walkforward.py` 가 레짐별 가중치 합이 1.0인지 검사한다.

**확신도는 판단 시점 값으로 고정해야 한다.** 방향이 유지되는 상태인데 확신도를
현재 봉 조건으로 다시 계산하면 보유 중에 0으로 붕괴한다. 볼린저 평균회귀의
평균 확신도가 0.109 로 나와 실력과 무관하게 앙상블에서 저평가됐다.
`strategies/base.py` 의 `latch()` 가 진입 시점 값을 끌고 간다.
